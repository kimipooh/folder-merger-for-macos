# 設計と実装

[README](../README.md) · [日本語マニュアル](user-guide-ja.md) · [English guide](user-guide-en.md) · [配布計画](release.md)

## 構成と不変条件

`App/FolderMergerApp.swift` は SwiftUI の WindowGroup と Settings シーンを提供する。AppSettings は設定の読込み・保存、MergeModel は入力一覧・構成検証・開始時スナップショット・バックグラウンド実行・進捗バッファ・結果表示を担当する。Foundation/AppKit の選択パネルと Finder 表示を使用する。

`Sources/FolderMergerCore/MergeEngine.swift` は UI に依存しない Swift Package の統合エンジンで、検証、走査、比較、コピー、属性適用、確定、後片付けを行う。`run` は MergeResult（状態・出力 URL・件数・警告・エラー）を返し、MergeEvent と MergeProgress で通知する。従来の `merge` は URL を返す互換 API で、警告を取得する場合は `run` を使用する。

不変条件は「入力を変更しない」「既存の出力先を上書きしない」。入力を移動・改名・削除せず、内容と更新日時を変更しない。ただし読取りによるアクセス日時の更新は抑制しない。入力全体の時点スナップショットは作成しないため、実行中は他のアプリでも入力・保存先を変更しないこと。

対応は macOS 13.0 以降（Package.swift と Xcode deployment target）。App Sandbox は無効、現在は CODE_SIGNING_ALLOWED=NO。ユーザー権限で動き、macOS のプライバシー保護によるアクセス許可が別途必要になりうる。バンドル ID は仮の `org.foldermerger.local`、表示バージョン 1.0、ビルド番号 1。外部依存、Sparkle、自動更新はない。手動の更新確認メニューを About の直後に追加し、Settings は維持する。

## 手動の更新確認

`UpdateChecker.swift` は UI から独立した版解析・URL 検証・HTTP 分類を提供する。`UpdateTransport` を固定応答に差し替えて swift test で検証する。版は非負整数のドット区切りで、タグの先頭 v/V と末尾のゼロ成分を許容する。整数文字列の長さと辞書順で比較し、桁あふれを避ける。不正な現在版・タグ、draft/prerelease は不正応答とする。

`UpdateModel` はメニュー選択時だけ非同期に GitHub の `releases/latest` へ接続する。Accept と個人情報を含まない User-Agent を設定し、要求15秒・全体30秒のタイムアウト、永続キャッシュなし、リダイレクト拒否とする。確認・結果表示中は重複実行を防ぎ、終了時は再実行可能。MergeModel や属性設定を変更しない。

HTTP 404、レート制限（403/429・残数0）、通信失敗、その他の不正応答を区別する。公開版が新しい場合だけ検証済み HTTPS の当該 GitHub リポジトリの releases 配下へブラウザを開ける。scheme・host・パスの大文字小文字差、userinfo、port、別ホスト・別リポジトリは拒否する。ダウンロード・インストール・再起動は利用者が行う。結果文言と手順は日英マニュアルを参照。

## 入力順と走査

入力ルートの名前を出力に含めず、各ルート直下からの相対パスを保つ。選択パネルでは panel.urls の順で一覧の末尾に追加する。Finder ドロップは各 provider の loadItem が非同期で完了し、メインキューに届いた順に追加するため、Finder 側の選択順や provider 配列順は保証しない。画面の上から順が統合時の優先順位になる。並べ替え UI はないので、必要なら削除して個別に追加し直す。

エンジンは request.inputs の順に深さ優先走査する。各ディレクトリ内は readdir の順でソートしない。同じ相対パスで最初に見つかった項目を計画に残す。空フォルダも作る。

入力不足、統合先の存在・フォルダ種別・シンボリックリンクでないこと・空であること、入力同士と統合先の双方向の重複・入れ子を検証し、UI では統合を無効化、実行時にも再検証する。device/inode と祖先を照合し、途中の別名・シンボリックリンク経由の重複も検出する。入力ルートのシンボリックリンク、内部のシンボリックリンク（壊れたものも含む）、FIFO・ソケット・デバイス等は拒否する。内部リンクはたどらない。`.DS_Store` は全階層で除外し、他の隠しファイルは処理する。

## 衝突の判定

相対パスは各成分の正準合成形と生 UTF-8 を照合し、異なる表記について保存先の排他的な専用一時フォルダで実測する。正準合成形のファイルを作成し、元表記の lstat が同じ device/inode を指す場合だけ同一名とする。結果は成分の生 UTF-8 ごとにキャッシュする。判定失敗は中止し、判定用フォルダも削除する。保存先が正規化を区別する成分は生 UTF-8 キーを使う。大小文字の変換はしない。

同じキーのフォルダは統合し、先の入力の表記・属性を計画に残す。子の出力パスにも採用済み親フォルダの表記を使う。ファイルは stat のサイズを比較し、同じなら最大 1 MiB のバッファで全バイト列を比較する。同一内容なら後続を省略し、現在の採用元を維持する。異なる内容なら SamePathPolicy の stop / earlier / later / newer を適用する。3入力以上でも一覧順に現在の採用元と次候補を比較する。newer は st_mtimespec の秒・ナノ秒を整数で比較し、同時刻・比較不可なら相対パス・両入力元・理由を示して中止する。採用元更新時も出力名は先の表記を保ち、内容と属性の参照元を一緒に差し替える。

ファイルとフォルダの種別衝突は失敗とする。キーが異なる名前でも、構築時の mkdir または `open(O_CREAT | O_EXCL | O_NOFOLLOW)` が EEXIST を返せば、作成済み項目の device/inode と照合して衝突を報告する。大小文字だけの違いは従来どおり、保存先が同一視する場合に中止し、case-sensitive なら別項目として保存する。自動改名・既存出力への上書きはしない。

## 設定・属性・コピー

属性保持設定の実装上の既定値はファイル日付オン、ファイル権限オン、フォルダ日付オフ、拡張属性オン。UserDefaults の保存値があれば優先する。安定キーは `merge.preserveFileDates`、`merge.preserveFilePermissions`、`merge.preserveDirectoryDates`、`merge.preserveExtendedAttributes`。AppSettings の didSet で保存する。未保存の拡張属性設定を読むだけでは保存しない。同名ファイルの優先設定は `merge.samePathPolicy` に保存し、未設定・不正値は earlier（「先に追加した入力フォルダを優先」）。UI は「同じ場所に内容の異なるファイルがある場合」で「統合を中止する」「先に追加した入力フォルダを優先」「後に追加した入力フォルダを優先」「変更日が新しいファイルを優先」を提供する。詳細ログは保存せず毎起動オフ。

start 時に値型の MergeRequest（MergeOptions を含む）と detailedLog を捕捉し、MergePlanDescription も保存する。実行中の設定変更は次回のみ適用し、実行中・前回の説明も開始時のまま保つ。

通常ファイルの内容は POSIX open/read/write による最大 1 MiB 単位のコピー。clone/copyfile API は使用せず、rsync 等の外部コマンドも起動しない。全体をメモリに載せない。入力は O_RDONLY | O_NOFOLLOW | O_NONBLOCK で開き、fstat で通常ファイルを確認する。

| 設定 | オン時の処理 | オフ時 |
| --- | --- | --- |
| ファイル日付 | stat で捕捉した mtime と birthtime を適用 | 新規作成値 |
| ファイル権限 | chmod で st_mode & 0777 を適用 | open(..., 0666) と umask |
| フォルダ日付 | 子の処理後、深い階層から mtime と birthtime を適用 | 新規作成・更新値 |
| 拡張属性・リソースフォーク | ファイルと内部フォルダの listxattr/getxattr/setxattr（XATTR_NOFOLLOW）で列挙された名前・値を複製 | 元から明示的に複製しない |

内容 → 拡張属性 → ファイル権限 → mtime（utimensat）→ 作成日（setattrlist/ATTR_CMN_CRTIME）の順。読み取り専用の権限も書込み後に適用する。内部フォルダの属性は子の作成完了後、深い順に適用する。同じ位置のフォルダは最初の入力、ファイルは最終採用元から属性を取得し、後続の属性を足し合わせない。出力ルートには入力ルートの日時・権限・拡張属性を継承しない。内部フォルダの権限は mkdir(..., 0777) と umask に従い、選択した統合先の権限は変更しない。

アクセス日時、所有者・グループ、ACL は複製しない。実行権限以外の特殊モードビットも保持対象外。拡張属性は com.apple.ResourceFork、Finder タグ、FinderInfo、com.apple.quarantine 等も除外せずコピーする。隔離扱いも出力へ引き継がれる。OS 保護属性の設定が EPERM 等になれば失敗する。保存先への属性適用の ENOTSUP/EOPNOTSUPP のみ警告にして続行し「警告ありで完了」。属性の読取り失敗、その他の適用エラー、内容 I/O エラーは中止する。

写真・動画の EXIF 等はファイル内容としてそのままコピーする。Takeout の付属 JSON は独立ファイルとしてコピーするだけで写真へ書き戻さない。ZIP 解凍や撮影日時補正も行わない。

## 進捗とログ

「処理内容を表示」は初期状態で閉じている。入力優先順、確定先、属性設定、同一ファイル・衝突・除外規則、一時フォルダ、RENAME_EXCL、コピー方式を説明する。各 ExecutionStep の外部コマンド引数は nil。

「作業ログ」は常時表示する。走査では検出件数（総数未確定）、構築では処理件数 / 総件数、現在の相対パスとコピー済みバイト数を表示する。段階・採用判断・警告・エラー・キャンセル・完了は詳細設定によらず通知する。fileSelected イベントは相対パス、採用元・不採用元・ルールを表示し、FileSelection に selectedInput / rejectedInput / policy と、newer の場合は双方の FileModificationTime（秒・ナノ秒）を保持する。判断順に最終採用元を追える。CSV/TXT 保存は実行後に利用できる。コピー・同一ファイル省略・警告・エラーの件数と最終状態を保持する。

既定ではフォルダ作成・ファイルコピー・同一ファイル省略の個別イベントを出さない。設定の「ログ」→「ファイルごとの詳細ログ」をオンにすると、実際に終えた処理を時刻、相対パス、採用元または省略元の入力、ファイルのバイト数とともに画面表示する。保存用ジャーナルへの記録は常に行う。コピー件数は内容コピー完了時に加算され、その後の属性エラーで全体が失敗しても実行済み件数として残る。

ワーカーバッファと画面は各最大 5,000 行。約 150 ms 以上の間隔でメインキューへ反映し、終了時に即時 flush する。除外した行数を表示する。件数・最終状態・失敗内容・警告配列は行数上限と別に保持するが、UI の属性警告の詳細は先頭 1,000 件と残件数のみ表示する。ログはファイルへ自動保存しない。ログ・パス・エラーは選択してコピーできる。

## 一時出力・確定・中断

選択した空の統合先を `MergeRequest.output` とし、追加階層を作らない。ダイアログは「統合先フォルダを選択…」/ `Choose Destination Folder…`、`canCreateDirectories = true` により標準の「新規フォルダ」を利用する。隠し項目を含めて検査し、`.DS_Store` のみ空判定から除外する。これは読みも削除もしない。選択時と実行開始時に検証する。

統合先内に `.foldermerger-<UUID>.tmp` を mkdir(..., 0700) で排他的に作り、内部項目も排他的に構築する。Unicode probe も統合先内の UUID 名の専用フォルダ（0700）で実測し、成功・失敗とも削除する。構築と確定が同じボリュームなので、入力が別ボリュームでもコピーできる。

統合先フォルダ全体の rename は inode・作成日・権限・ACL・Finder タグを置き換えるため採用しない。代わりに統合先の device/inode を再確認し、`.DS_Store` と自分の一時フォルダ以外がないことを再検査する。開いたディレクトリ記述子を基準に、構築済みの直下項目を `renameatx_np(RENAME_EXCL)` で移動する。入力ルートの属性は統合先へ適用せず、権限も変更しない。項目追加による統合先の更新日時の変化はある。

確定中に衝突等で失敗した場合、移動済み項目の device/inode を照合して逆順に一時フォルダへ排他的に戻し、一時フォルダを削除する。他の処理が追加した項目、`.DS_Store`、統合先自体には触れず、確定前の状態へ戻す。複数項目全体は原子的に可視化されない。実行中は他のアプリで入力・統合先を変更しない。外部による移動済み項目の置換や I/O 障害で復元できない場合は、削除を続行せず後片付け失敗と対象パスを報告する。

キャンセルは走査・比較・コピーのチャンク境界、確定開始直前まで確認する。確定開始後はキャンセルを保留し、確定完了または失敗時のロールバック完了に統一する。確定前の失敗・キャンセルでは同期 I/O と close 後に一時フォルダだけを削除し、空の統合先と既存 `.DS_Store` を残す。後片付け失敗は一時パスを報告する。強制終了・電源断では一時フォルダや確定途中の項目が残りうる。アプリの停止を確認してから手動で確認する。

## ローカライズと依存関係

App/Localizable.xcstrings と Sources/FolderMergerCore/Resources/Localizable.xcstrings が日英の正本。開発言語は英語、コアは Swift Package の Bundle.module を使用する。macOS のシステム／アプリ別言語に従い、非対応言語は英語へフォールバックする。パスは翻訳しない。設定メニューは SwiftUI Settings シーンが提供し、カタログ内の独自文字列ではない。

Package.swift に外部依存はなく、xcodeproj はローカルの FolderMergerCore のみ参照する。リソースは日英カタログのみで、第三者コード・素材の同梱は確認されない。Apple のシステムフレームワークを利用する。Sparkle は未導入。現行配布は Developer ID 署名・Apple 公証なしの ZIP と手動入れ替え。

## コピー方式の検討記録（移設）

旧検証環境の `/usr/bin/rsync --version` は `openrsync: protocol version 29` / `rsync version 2.6.9 compatible` でした。`--times` の人工データでの動作も確認しています。rsync は第一候補として検討しましたが、内容の厳密な比較、チャンクごとのキャンセル、保存先での名前衝突の検出を一つの処理で管理するため、Foundation と POSIX の `open/read/write` を採用しました。統合処理から外部プロセスは起動しません。

## 作業ログの保存

実行後の「ログを保存…」（`Save Log…`）では「ログの種類」（「簡易ログ」/ `Summary log`、 「詳細ログ」/ `Detailed log`）と「形式」（「TXT（UTF-8）」、「CSV（UTF-8 BOM 付き）」、英語は `TXT (UTF-8)`、`CSV (UTF-8 with BOM)`）を別々に選べます。既定は簡易ログ／TXT。既定名は `FolderMerger-summary-log-20261112-120500.txt` のように種類と日時を含み、種類の変更で `summary` / `detailed` が、形式の変更で拡張子が変わります。手入力した名前の本体は維持します。場所と名前を選び、既存ファイルの置換は標準の確認に従います。保存失敗はアラートで表示します。未実行・実行中は保存できませんが、成功、警告付き完了、失敗、キャンセル、開始前の検証失敗では4通りすべてを保存できます。

「ファイルごとの詳細ログ」は画面表示だけを制御します。オフでもコピー・フォルダ作成・同一内容の省略を含む全イベントを一時ジャーナルに逐次記録し、後から詳細ログを保存できます。画面の5,000行上限とは独立しています。実行条件には「ファイルごとの詳細ログ（画面表示）」として記録します。

簡易ログは、開始・終了時刻、追加順付き入力一覧、出力予定先、適用ルール、属性保持4設定、結果、コピー・省略・警告・エラー・フォルダ作成・採用結果の件数を含みます。同名ファイルの最終採用元、採用判断で不採用となった全入力元とルール、警告・エラー・キャンセル・衝突中止を残します。通常のコピー、フォルダ作成、同一内容の省略、個々の採用判断の経過、フェーズは個別行を出しません。同一内容の入力元は不採用元に含めません。簡易 TXT は「実行条件」→「同名ファイルの採用結果」（件数・各件）→「警告・エラー」→「最終結果」の節で構成します。

簡易 CSV の列は「区分、相対パス、採用元、不採用元、適用ルール、詳細、保護した列」です。「区分」で実行条件、入力元、同名ファイルの採用結果、警告、失敗、キャンセル、衝突による中止、最終結果を絞り込めます。不採用元は `; `（セミコロンと空白）区切りで、パス自体にもこの文字列がある場合は区別できません。

詳細ログは個別操作と判断経過を時系列で保存します。詳細 CSV は「時刻、処理、相対パス、入力元、比較対象、判定、適用ルール、入力元の変更日時、比較対象の変更日時、詳細、保護した列」の11列を維持します。入力元は採用側または記録対象、比較対象は不採用側（同一内容の省略では既存の採用側）です。最終採用行の比較対象には全不採用元を `; ` 区切りで記録し、判定には走査完了状態、詳細には出力確定状態を記録します。時刻と新しい変更日時での比較は ISO 8601、ナノ秒9桁、端末のローカルUTCオフセット付きです。詳細 TXT は「実行条件」→「同名ファイルの採用結果」→「作業ログ（時系列）」→「最終結果」の順です。

両方の CSV は UTF-8 BOM 付き、RFC 4180、CRLF。両方の TXT は UTF-8 BOM なし、LFで、値内のCR・改行を `\r`・`\n` と表示します。CSV は先頭の `=`・`+`・`-`・`@`・TAB・CR・LF・全角 `＝`・`＋`・`－`・`＠` を数式として解釈させないよう `'` を1文字付けます。Unicode空白や制御・書式文字を挟んだ場合も判定し、元から `'` で始まる値は変更しません。

「保護した列」（`Protected columns`）は保護した列の固定識別子を列順に `;` 区切りで記録します。簡易 CSV は `category`, `relative_path`, `selected_input`, `rejected_inputs`, `applied_rule`, `details`。詳細 CSV は `time`, `action`, `relative_path`, `input`, `compared_with`, `decision`, `applied_rule`, `input_modified`, `compared_modified`, `details`。CSVをパーサで読んだ後、挙がった列だけ先頭の `'` を1文字除くと元の値へ復元できます。空欄は保護なしです。見出しも同じ保護を適用します。表計算画面の見え方に依存せず元の CSV とメタデータを使って復元してください。TXT・画面は元表記です。

成功・警告付き完了では「出力確定」のパスと「採用結果は確定した出力に反映されています。」を確認してください。失敗・キャンセルでは「出力は確定していません。以下は採用判断です。」と後片付け結果を確認します。簡易 TXT の採用結果節と最終結果節の両方で未確定を示します。走査途中で停止した場合は「走査未完了のため、判断済み分のみ表示しています」と注記します。判断が残っていても完成出力があるとは限りません。

保存時は一時ジャーナルをストリーム変換し、全件をメモリに保持しません。次回実行と終了時に一時ログを削除します。記録失敗は統合を止めず「ログは不完全です」と理由を示します。ログは入力パスを含みます。入力・統合出力へ自動保存・同梱しません。

## 同名ファイルの採用結果

入力一覧の番号（1、2、3…）が追加順を示し、「先に追加した入力フォルダを優先」「後に追加した入力フォルダを優先」はこの順序を指します。新しい既定値は「先に追加した入力フォルダを優先」です。「統合を中止する」を含む保存済み設定は維持し、起動時に既定値を書き込みません。見出し直下には待機中・終了後は現在の設定、統合中は開始時に取得した「この実行のルール」を表示します。統合中に現在の設定が開始時のルールと異なる場合だけ「変更したルールは次回の統合から適用します」を表示し、終了時に消します。「同名ファイルの採用結果」と保存ログには実際に使用したルールを残します。

作業ログ内の独立区画「同名ファイルの採用結果」（英語: `Conflicting File Decisions`）は詳細ログオフでも表示します。内容が異なり判断した相対パスを数え、同一内容だけの省略は含めません。出力表記の相対パス、最終採用元、採用判断で不採用となった入力元、適用ルールを表示します。同一内容で省略した入力元は不採用元に含めず、時系列ログの省略記録で確認できます。画面は最大1,000件で「ほか N 件（保存ログに全件）」を表示し、件数と保存ログは全件を対象にします。未実行時と実行中は未確定の注記を表示しません。成功時は「採用結果は確定した出力に反映されています。」、失敗・キャンセル時は「出力は確定していません。以下は採用判断です。」を表示します。走査途中の失敗では「走査未完了のため、判断済み分のみ表示しています」と示します。

詳細 TXT は実行条件の後、時系列ログの前に同名の節を置き、件数・各件と出力の確定状態を示します。詳細 CSV は10列＋「保護した列」を維持し、「処理」を「同名ファイルの採用結果」で絞り込めます。「相対パス」「入力元」「比較対象」「適用ルール」にそれぞれ出力パス・採用元・採用判断で不採用となった入力元（`; ` 区切り）・ルールを記録します。「判定」は走査の完了状態、「詳細」は出力の確定状態です。追加値にも既存の数式保護・復元規則が適用されます。TXT と画面は元表記です（TXT の改行・CR は既存規則どおりエスケープ）。

構造化イベント `finalSelection` は `ConflictingFileDecision`（相対パス、採用元、内容差のある比較で不採用となった入力元、ルール、走査完了フラグ）を持ちます。同一内容で省略した入力元は不採用一覧に含めず、時系列の省略イベントで追跡できます。走査完了時、または走査失敗時の判断済み分を発行します。画面用 `ConflictingFileDecisions` は件数と先頭1,000件だけを保持します。TXT はジャーナルを再読して独立節を生成し、全件配列を作りません。確定状態は `MergeResult.output` の有無から取得し、走査結果と区別します。
