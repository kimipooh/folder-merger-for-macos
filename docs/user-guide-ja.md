# 利用マニュアル（日本語）

[README](../README.md) · [English](user-guide-en.md) · [設計](design.md) · [配布計画](release.md)

## 1. 概要と準備

macOS 13.0 以降で、複数フォルダの中身を新しいフォルダへまとめます。入力ルートの名前は含めず、その直下からの相対パスを保ちます。入力の移動・改名・削除や、既存出力への追記・上書きはしません。空フォルダも作ります。配布済み Release はまだありません。[ソースからのビルド](../README.md)を利用してください。

アプリはユーザー権限で動き、App Sandbox は無効です。macOS が求めるフォルダへのアクセス許可が必要になることがあります。実行中は他のアプリでも入力・保存先を変更しないでください。入力全体の時点スナップショットは作りません。読取りにより入力のアクセス日時が更新される可能性があります。

表示言語は macOS のシステム／アプリ別言語に従い、日本語・英語に対応します。非対応言語は英語になります。アプリ内の言語切替はありません。ファイル名とパスは翻訳しません。

### 入手・起動と手動アップデート

ソースは [GitHub の main](https://github.com/kimipooh/folder-merger-for-macos/tree/main) で公開する方針です。Release はまだありません。公開後は [GitHub Releases](https://github.com/kimipooh/folder-merger-for-macos/releases) のアプリ入り ZIP を選びます。GitHub 自動生成の `Source code (zip)` はソースのみで、アプリは含みません。

Developer ID 署名・Apple 公証はありません。初回起動がブロックされた場合は、一度起動を試す →「システム設定」→「プライバシーとセキュリティ」→「このまま開く」の順に進みます。新版でも再許可が必要な場合があります。

1. Folder Merger メニューの「アップデートを確認…」を選びます。通信はこのメニューを選んだときだけで、起動時・定期確認や自動ダウンロード・インストール・再起動はありません。確認中は同じメニューを選べません。統合処理の状態・進行は変更しません。
2. 「新しいバージョンがあります。現在: <現在版>・公開版: <公開版>」なら「リリースページを開く」で既定ブラウザを開き、アプリ入り ZIP を取得して展開します。「キャンセル」ならページを開きません。
3. 旧版を終了してから `.app` を入れ替え、新版を起動します。同じバンドル ID の版同士では4つの属性保持設定が引き継がれます。詳細ログは毎起動オフです。

その他の結果は以下の意味です。完了・エラー後は再試行できます。

- 「現在のバージョンは最新です。」: 公開版が現在版と同じ、または古い版です。
- 「公開済みのリリースを取得できませんでした。」: HTTP 404。初回 Release 未公開の場合も含み、最新版という意味ではありません。
- 「GitHub のレート制限に達しました。時間をおいて再試行してください。」: レート制限です。
- 「通信エラーが発生しました。再試行してください。」: 接続失敗やタイムアウトです。
- 「更新サーバーから不正な応答が返されました。」: 応答、タグ、URL 等が不正です。draft・prerelease も正式版として扱いません。


## 2. 入力フォルダと順序

「入力フォルダを追加…」で複数のフォルダを選ぶか、Finder から「入力フォルダ（Finder からドロップできます）」へドロップします。一覧にフルパスが表示され、不要な項目は「削除」で除けます。入力元のファイルは削除されません。

統合時の優先順位は一覧の上から順です。選択パネルでは返された順に末尾へ追加します。複数ドロップでは非同期読込みの完了順で追加されるため、Finder での選択順は保証しません。必ず一覧を確認してください。並べ替え機能はないので、優先順が必要なら削除して一つずつ追加し直します。同じ位置のファイル・フォルダの属性は最初の入力から採用します。

入力ルートのシンボリックリンク、入力同士の重複・入れ子は使えません。内部のシンボリックリンク（壊れたものも含む）、FIFO・ソケット・デバイス等も処理できません。`.DS_Store` は全階層で除外し、他の隠しファイルは処理します。

## 3. 保存先・実行・結果

「保存先親フォルダを選択…」で入力の外にある親フォルダを選び、「出力フォルダ名」に新しい名前を入力します。「作成先:」に続くパスを確認します。空白のみ、`.`、`..`、`/`・`:`・NUL を含む名前は使えません。同名の既存項目（リンクを含む）があれば別の名前にしてください。

構成エラーが解消したら「統合」を押します。処理中は入力・保存先・名前の編集はできません。走査・比較・コピーはバックグラウンドで動きます。完了後の「Finder で表示」で出力を確認します。エラーとパスは選択・コピーできます。

## 4. 使用例

汎用例: `Folder A/reports/a.txt` と `Folder B/reports/b.txt` を入力とし、別の親フォルダで出力名を `Combined` にすると、`Combined/reports/a.txt` と `Combined/reports/b.txt` ができます。入力フォルダ自体の名前は出力に入りません。

Google Takeout 例: 分割取得後に展開済みの `Takeout`、`Takeout 2`、`Takeout 3` を追加し、入力の外にある親フォルダで出力名を `Takeout` にします。元フォルダを改名する必要はありません。以下はすべて人工名です。

```text
Takeout/Google Photos/Album/IMG.jpg
Takeout 2/Google Photos/Album/video.mp4
Takeout 3/Google Photos/Album/IMG.jpg.json
→ <destination>/Takeout/Google Photos/Album/IMG.jpg
→ <destination>/Takeout/Google Photos/Album/video.mp4
→ <destination>/Takeout/Google Photos/Album/IMG.jpg.json
```

ZIP 解凍や撮影日時の補正はしません。先にアーカイブを展開してください。

## 5. 設定と属性の保持

アプリメニュー「Folder Merger → 設定…」、または `⌘,` で開きます（英語は「Folder Merger → Settings…」）。これは SwiftUI の標準 Settings シーンが提供するメニューで、アプリの文字列カタログには独自定義がありません。

「属性の保持」には次の4項目があります。既定値は未保存の設定にだけ使われます。既存ユーザーの保存済みオン・オフはそのまま使われます。

| 設定名 | 初回既定値 | 残る情報・使いどころ |
| --- | --- | --- |
| ファイルの作成日・変更日を保持 | オン | Finder のファイル作成日と変更日。元の日付を残したいときに使います。 |
| ファイルのアクセス権を保持 | オン | 読取り・書込み・実行の権限ビット。通常はオンにします。所有者・グループ・ACL は含みません。 |
| フォルダの作成日・変更日を保持 | オフ | フォルダ自体の作成日と変更日。フォルダの日付も記録として残したい場合にオンにします。 |
| Finderタグなど、Mac固有の情報も保持 | オン | ファイルと内部フォルダの拡張属性・リソースフォーク（Finder タグ等）。通常はオンにします。 |

各項目の説明は常時表示され、「詳細」で技術名、Takeout の内容、非対応属性の警告の説明を開けます。以前から保存済みの Mac 固有情報の設定がオフなら、現在の既定値オンへ自動変更しません。未保存設定を読み込むだけでは保存されません。

同じ位置のファイル・フォルダは、入力一覧の最初の項目から属性を採用します。後続の属性は合成しません。内容が同じファイルも最初の属性を使います。出力最上位フォルダには入力ルートの日時・属性・権限を引き継ぎません。フォルダの属性は子の作成後に適用します。

オフの属性は元から明示的に複製せず、OS の新規作成値を使います。ファイル権限オフ時は 0666 に umask を適用、フォルダ権限は常に 0777 に umask を適用します。アクセス日時、所有者・グループ、ACL は保持しません。

4項目は UserDefaults に保存され、再起動後も復元されます。「ログ」内の「ファイルごとの詳細ログ」は保存されず、起動時は常にオフです。実行中にも設定ウィンドウを変更できますが、属性・詳細ログの変更は次回の統合から反映されます。進行中の統合は開始時の設定を使い続けます。

## 6. ファイル内容と Mac 固有情報

通常ファイルは最大 1 MiB 単位の POSIX コピーで内容をそのまま複製します。拡張属性設定は Finder タグやリソースフォーク等の付属情報に関係します。写真・動画の EXIF 等はファイル内容の一部なので設定にかかわらずコピーされます。Google Takeout の JSON は独立ファイルとしてコピーするだけで、写真へ情報を書き戻しません。

拡張属性オンでは `com.apple.quarantine` も引き継ぎ、出力も隔離扱いになる場合があります。OS が保護する属性（例 `com.apple.rootless`）の書込みが EPERM で拒否されると処理は失敗します。保存先への属性適用が ENOTSUP/EOPNOTSUPP の場合のみ警告として続行します。その他の属性エラー・属性読取りエラー・内容の読み書きエラーは中止します。

## 7. 処理内容・進捗・作業ログ

「処理内容を表示」を開くと、入力順・確定先・属性設定・統合規則・コピー方式を確認できます。既定は閉じています。「次回の実行予定」と「実行中の内容（開始時点）」または「前回の実行内容（開始時点）」を区別して表示します。設定変更で過去の説明は変わりません。

「作業ログ」は既定で表示され、段階、現在の項目、コピー・同一ファイル省略・警告・エラーの件数、最終結果を確認できます。走査中は検出件数、構築中は処理件数 / 総件数とコピー済みバイト数が表示されます。

設定の「ログ」で「ファイルごとの詳細ログ」をオンにすると、次回からフォルダ作成・ファイルコピー・同一ファイル省略の個別ログが増えます。時刻、相対パス、採用元／省略元入力、ファイルのバイト数を表示します。既定オフでも警告・エラー・キャンセル・完了は表示します。コピー件数は内容コピーの完了時に増えるので、後の属性エラーで失敗した場合も実行済み件数として残ります。

表示とバッファは各最大 5,000 行で、除外行数を表示します。約 150 ms 間隔で反映し終了時は即時反映します。件数・最終結果・警告配列・失敗内容は行数上限とは別に保持しますが、属性警告の詳細表示は先頭 1,000 件と残件数に限ります。ログは選択してコピーできます。ログファイルの自動保存機能はありません。

## 8. 衝突・警告・キャンセル

同じ相対パスのフォルダは統合します。ファイルはサイズと全バイト列が同じ場合だけ1件へまとめます。更新日時だけでは判定しません。内容の違い、ファイルとフォルダの衝突、保存先で同一視される別表記の名前は中止します。大文字小文字や Unicode の NFC/NFD の扱いは保存先の実際の排他的作成に従い、別表記の衝突は同じ内容でも中止します。両方の相対パスと入力フルパスを確認し、元データの扱いを判断してください。上書きや自動改名はありません。

「警告ありで完了」は内容のコピーは完了したものの、一部属性が保存先で非対応だった状態です。属性警告で対象パス・属性・理由を確認してください。「失敗」は完成出力を作りません。

「キャンセル」は走査・比較・コピーのチャンク境界などで反映され、停止・ファイルのクローズ・一時フォルダの後片付け後に再操作できます。完成した出力名は残しません。確定済みの成功出力はキャンセルで削除しません。

出力は親フォルダ内の `.<出力名>.foldermerger-<UUID>.tmp` で構築後、既存項目を上書きしない rename で確定します。後片付け失敗時は一時パスを表示します。強制終了・電源断では残ることがあるため、アプリを終了して停止を確認してから該当一時フォルダを手動で片付けてください。
