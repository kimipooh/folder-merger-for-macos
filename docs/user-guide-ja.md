# 利用マニュアル（日本語）

[README](../README-ja.md) · [English](user-guide-en.md) · [設計](design.md) · [配布計画](release.md)

## 1. 概要と準備

macOS 13.0 以降で、複数フォルダの中身を選んだ空の統合先フォルダへ直接まとめます。入力ルートの名前は含めず、その直下からの相対パスを保ちます。入力の移動・改名・削除や、既存項目への上書きはしません。空フォルダも作ります。配布済み Release はまだありません。[ソースからのビルド](../README-ja.md)を利用してください。

アプリはユーザー権限で動き、App Sandbox は無効です。macOS が求めるフォルダへのアクセス許可が必要になることがあります。実行中は他のアプリでも入力・保存先を変更しないでください。入力全体の時点スナップショットは作りません。読取りにより入力のアクセス日時が更新される可能性があります。

表示言語は macOS のシステム／アプリ別言語に従い、日本語・英語に対応します。非対応言語は英語になります。アプリ内の言語切替はありません。ファイル名とパスは翻訳しません。

### 入手・起動と手動アップデート

ソースは [GitHub の main](https://github.com/kimipooh/folder-merger-for-macos/tree/main) で公開する方針です。Release はまだありません。公開後は [GitHub Releases](https://github.com/kimipooh/folder-merger-for-macos/releases) のアプリ入り ZIP を選びます。GitHub 自動生成の `Source code (zip)` はソースのみで、アプリは含みません。

Developer ID 署名・Apple 公証はありません。初回起動がブロックされた場合は、一度起動を試す →「システム設定」→「プライバシーとセキュリティ」→「このまま開く」の順に進みます。新版でも再許可が必要な場合があります。

1. Folder Merger メニューの「アップデートを確認…」を選びます。通信はこのメニューを選んだときだけで、起動時・定期確認や自動ダウンロード・インストール・再起動はありません。確認中は同じメニューを選べません。統合処理の状態・進行は変更しません。
2. 「新しいバージョンがあります。現在: <現在版>・公開版: <公開版>」なら「リリースページを開く」で既定ブラウザを開き、アプリ入り ZIP を取得して展開します。「キャンセル」ならページを開きません。
3. 旧版を終了してから `.app` を入れ替え、新版を起動します。同じバンドル ID の版同士では4つの属性保持設定と同名ファイルの優先設定が引き継がれます。詳細ログは毎起動オフです。

その他の結果は以下の意味です。完了・エラー後は再試行できます。

- 「現在のバージョンは最新です。」: 公開版が現在版と同じ、または古い版です。
- 「公開済みのリリースを取得できませんでした。」: HTTP 404。初回 Release 未公開の場合も含み、最新版という意味ではありません。
- 「GitHub のレート制限に達しました。時間をおいて再試行してください。」: レート制限です。
- 「通信エラーが発生しました。再試行してください。」: 接続失敗やタイムアウトです。
- 「更新サーバーから不正な応答が返されました。」: 応答、タグ、URL 等が不正です。draft・prerelease も正式版として扱いません。


## 2. 入力フォルダと順序

「入力フォルダを追加…」で複数のフォルダを選ぶか、Finder から「入力フォルダ（Finder からドロップできます）」へドロップします。一覧にフルパスが表示され、不要な項目は「削除」で除けます。入力元のファイルは削除されません。

統合時の優先順位は一覧の上から順です。選択パネルでは返された順に末尾へ追加します。複数ドロップでは非同期読込みの完了順で追加されるため、Finder での選択順は保証しません。必ず一覧を確認してください。並べ替え機能はないので、優先順が必要なら削除して一つずつ追加し直します。同じ位置のフォルダ属性は最初の入力、ファイル属性は下記のルールで採用したファイルから取得します。

入力ルートのシンボリックリンク、入力同士の重複・入れ子は使えません。内部のシンボリックリンク（壊れたものも含む）、FIFO・ソケット・デバイス等も処理できません。`.DS_Store` は全階層で除外し、他の隠しファイルは処理します。

## 3. 保存先・実行・結果

「統合先フォルダを選択…」で入力と重複・入れ子でない空のフォルダを選び、表示されたパスを確認します。標準ダイアログの「新規フォルダ」で作成できます。隠しファイルやサブフォルダがあれば選び直してください。`.DS_Store` だけは空判定で無視し、読みも削除もしません。未選択・空でない場合は「統合」が無効になります。選んだフォルダ自体に直接出力し、名前入力や追加の階層はありません。

構成エラーが解消したら「統合」を押します。処理中は入力・統合先の編集はできません。走査・比較・コピーはバックグラウンドで動きます。完了後の「Finder で表示」で出力を確認します。エラーとパスは選択・コピーできます。

## 4. 使用例

汎用例: `Folder A/reports/a.txt` と `Folder B/reports/b.txt` を入力とし、空の統合先フォルダ `Combined` を選ぶと、`Combined/reports/a.txt` と `Combined/reports/b.txt` ができます。入力フォルダ自体の名前は出力に入りません。

Google Takeout 例: 分割取得後に展開済みの `Takeout`、`Takeout 2`、`Takeout 3` を追加し、入力と重複・入れ子でない空の統合先フォルダ `Takeout` を選びます。元フォルダを改名する必要はありません。以下はすべて人工名です。

```text
Takeout/Google Photos/Album/IMG.jpg
Takeout 2/Google Photos/Album/video.mp4
Takeout 3/Google Photos/Album/IMG.jpg.json
→ <destination>/Takeout/Google Photos/Album/IMG.jpg
→ <destination>/Takeout/Google Photos/Album/video.mp4
→ <destination>/Takeout/Google Photos/Album/IMG.jpg.json
```

ZIP 解凍や撮影日時の補正はしません。先にアーカイブを展開してください。

## 5. 設定と属性の保持

アプリメニュー「Folder Merger → 設定…」、または `⌘,` で開きます（英語は「Folder Merger → Settings…」）。これは SwiftUI の標準 Settings シーンが提供するメニューで、アプリの文字列カタログには独自定義がありません。

「属性の保持」には次の4項目があります。既定値は未保存の設定にだけ使われます。既存ユーザーの保存済みオン・オフはそのまま使われます。

| 設定名 | 初回既定値 | 残る情報・使いどころ |
| --- | --- | --- |
| ファイルの作成日・変更日を保持 | オン | Finder のファイル作成日と変更日。元の日付を残したいときに使います。 |
| ファイルのアクセス権を保持 | オン | 読取り・書込み・実行の権限ビット。通常はオンにします。所有者・グループ・ACL は含みません。 |
| フォルダの作成日・変更日を保持 | オフ | フォルダ自体の作成日と変更日。フォルダの日付も記録として残したい場合にオンにします。 |
| Finderタグなど、Mac固有の情報も保持 | オン | ファイルと内部フォルダの拡張属性・リソースフォーク（Finder タグ等）。通常はオンにします。 |

各項目の説明は常時表示され、「詳細」で技術名、Takeout の内容、非対応属性の警告の説明を開けます。以前から保存済みの Mac 固有情報の設定がオフなら、現在の既定値オンへ自動変更しません。未保存設定を読み込むだけでは保存されません。

同じ位置のフォルダ属性は入力一覧の最初の項目から、ファイル属性は採用したファイルから取得します。後続の属性は合成しません。同一内容の後続ファイルは省略し、現在採用中のファイルの属性を維持します。出力最上位フォルダには入力ルートの日時・属性・権限を引き継ぎません。フォルダの属性は子の作成後に適用します。

オフの属性は元から明示的に複製せず、OS の新規作成値を使います。ファイル権限オフ時は 0666 に umask を適用、内部フォルダ権限は常に 0777 に umask を適用します。入力からアクセス日時、所有者・グループ、ACL は複製しません。選択した統合先自体の属性・権限・ACL は保持します。

4項目は UserDefaults に保存され、再起動後も復元されます。「ログ」内の「ファイルごとの詳細ログ」は保存されず、起動時は常にオフです。実行中にも設定ウィンドウを変更できますが、属性・詳細ログの変更は次回の統合から反映されます。進行中の統合は開始時の設定を使い続けます。

「同じ場所に内容の異なるファイルがある場合」では次の4つを選べます。

- 「統合を中止する」
- 「先に追加した入力フォルダを優先」（既定）
- 「後に追加した入力フォルダを優先」
- 「変更日が新しいファイルを優先」

選択は再起動後も復元され、未設定・不正値は「先に追加した入力フォルダを優先」です。3入力以上でも一覧順に現在の採用ファイルと次の候補を比較し、内容が同じなら省略、異なる場合だけルールを適用します。「変更日が新しいファイルを優先」は入力の変更日時をナノ秒まで比較します。同時刻・比較不可なら相対パス・両入力元・理由を示して中止します。この設定も開始時に確定し、実行中の変更は次回から反映されます。

## 6. ファイル内容と Mac 固有情報

通常ファイルは最大 1 MiB 単位の POSIX コピーで内容をそのまま複製します。拡張属性設定は Finder タグやリソースフォーク等の付属情報に関係します。写真・動画の EXIF 等はファイル内容の一部なので設定にかかわらずコピーされます。Google Takeout の JSON は独立ファイルとしてコピーするだけで、写真へ情報を書き戻しません。

拡張属性オンでは `com.apple.quarantine` も引き継ぎ、出力も隔離扱いになる場合があります。OS が保護する属性（例 `com.apple.rootless`）の書込みが EPERM で拒否されると処理は失敗します。保存先への属性適用が ENOTSUP/EOPNOTSUPP の場合のみ警告として続行します。その他の属性エラー・属性読取りエラー・内容の読み書きエラーは中止します。

## 7. 処理内容・進捗・作業ログ

「処理内容を表示」を開くと、入力順・確定先・属性設定・統合規則・コピー方式を確認できます。既定は閉じています。「次回の実行予定」と「実行中の内容（開始時点）」または「前回の実行内容（開始時点）」を区別して表示します。設定変更で過去の説明は変わりません。

「作業ログ」は既定で表示され、段階、現在の項目、コピー・同一ファイル省略・警告・エラーの件数、最終結果を確認できます。走査中は検出件数、構築中は処理件数 / 総件数とコピー済みバイト数が表示されます。

設定の「ログ」で「ファイルごとの詳細ログ」をオンにすると、次回からフォルダ作成・ファイルコピー・同一ファイル省略の個別ログが増えます。時刻、相対パス、採用元／省略元入力、ファイルのバイト数を表示します。既定オフでも、内容の異なる同名ファイルの採用判断ごとに相対パス・採用元・不採用元・適用ルールを表示します。3入力以上では判断を順に追うことで最終採用元を確認できます。警告・エラー・キャンセル・完了も表示します。コピー件数は内容コピーの完了時に増えるので、後の属性エラーで失敗した場合も実行済み件数として残ります。

表示とバッファは各最大 5,000 行で、除外行数を表示します。約 150 ms 間隔で反映し終了時は即時反映します。件数・最終結果・警告配列・失敗内容は行数上限とは別に保持しますが、属性警告の詳細表示は先頭 1,000 件と残件数に限ります。ログは選択してコピーできます。ログファイルの自動保存機能はありません。

## 8. 衝突・警告・キャンセル

同じ相対パスのフォルダは統合します。ファイルはサイズと全バイト列が同じ場合だけ1件へまとめます。更新日時だけでは判定しません。内容が異なる場合だけ選択中の優先設定を適用します。Unicode の正準等価な表記違い（NFC/NFD 等）は各パス成分を保存先の一時領域で実測し、同一視される場合は同じパスとして統合します。表記は一覧で先の入力を使い、保存先が区別する場合は別項目です。ファイルとフォルダの衝突は中止します。大小文字だけが異なる名前は従来どおり保存先が同一視する場合に中止し、区別する場合は別項目として保存します。両方の相対パスと入力フルパスを確認し、元データの扱いを判断してください。上書きや自動改名はありません。

「警告ありで完了」は内容のコピーは完了したものの、一部属性が保存先で非対応だった状態です。属性警告で対象パス・属性・理由を確認してください。「失敗」は完成出力を作りません。

「キャンセル」は走査・比較・コピーのチャンク境界などで反映され、停止・ファイルのクローズ・一時フォルダの後片付け後に再操作できます。確定開始前のキャンセルでは統合先を元の空の状態（`.DS_Store` は保持）へ戻します。確定開始後はキャンセルを保留し、確定またはロールバックを完了させます。

出力は統合先内の `.foldermerger-<UUID>.tmp`（権限 0700）で構築し、空であることを再確認後、直下の項目ごとに排他的な `RENAME_EXCL` で確定します。途中の失敗では移動済みの項目を戻し、この実行の一時出力だけを片付けます。他の処理が追加した項目、`.DS_Store`、統合先自体は保持します。統合先の inode・作成日・権限・ACL・Finder タグは置き換えず、入力ルートの属性も適用しません。後片付け失敗時は一時パスを表示します。強制終了・電源断では残ることがあるため、アプリを終了して停止を確認してから該当一時フォルダを手動で片付けてください。

## 作業ログの保存

実行後の「ログを保存…」（`Save Log…`）では「ログの種類」（「簡易ログ」/ `Summary log`、 「詳細ログ」/ `Detailed log`）と「形式」（「TXT（UTF-8）」、「CSV（UTF-8 BOM 付き）」、英語は `TXT (UTF-8)`、`CSV (UTF-8 with BOM)`）を別々に選べます。既定は簡易ログ／TXT。既定名は `FolderMerger-summary-log-20261112-120500.txt` のように種類と日時を含み、種類の変更で `summary` / `detailed` が、形式の変更で拡張子が変わります。手入力した名前の本体は維持します。場所と名前を選び、既存ファイルの置換は標準の確認に従います。保存失敗はアラートで表示します。未実行・実行中は保存できませんが、成功、警告付き完了、失敗、キャンセル、開始前の検証失敗では4通りすべてを保存できます。

「ファイルごとの詳細ログ」は画面表示だけを制御します。オフでもコピー・フォルダ作成・同一内容の省略を含む全イベントを一時ジャーナルに逐次記録し、後から詳細ログを保存できます。画面の5,000行上限とは独立しています。実行条件には「ファイルごとの詳細ログ（画面表示）」として記録します。

簡易ログは「最終結果」→「コピーしたファイル」→「警告・エラー」の3節です。状態、確定したコピー件数、統合先、出力の確定状態を最初に示します。コピーは確定した出力ファイル1件につき「実際のコピー元 → 確定後のコピー先」の1行だけです。同名競合では最終採用元だけを示し、フォルダ行は出しません。入力・設定・採用判断の経過・同一内容の省略・処理段階は詳細ログで確認します。

簡易 CSV の列は「区分、コピー元、コピー先、内容、保護した列」（Category, Source, Destination, Details, Protected columns）です。区分は最終結果、コピー、警告、エラー、キャンセルなどです。コピー元とコピー先は絶対パスです。

詳細 TXT は「最終結果」→「入力と設定」→「作業ログ（時系列）」の順です。詳細 CSV の列は「時刻、処理、相対パス、コピー元・採用元、コピー先・不採用元、判定、理由、補足、保護した列」（Time, Operation, Relative Path, Source / selected input, Destination / rejected input, Decision, Reason, Notes, Protected columns）です。採用判断の判定欄には採用元と不採用元を明記し、理由は1文で示します。最終採用の走査状態と出力反映状態は補足に記録します。詳細ログのコピー行には、確定予定のコピー先がその時点で一時フォルダ内にあることを補足します。

両方の CSV は UTF-8 BOM 付き、RFC 4180、CRLF。両方の TXT は UTF-8 BOM なし、LFで、値内のCR・改行を `\r`・`\n` と表示します。CSV は先頭の `=`・`+`・`-`・`@`・TAB・CR・LF・全角 `＝`・`＋`・`－`・`＠` を数式として解釈させないよう `'` を1文字付けます。Unicode空白や制御・書式文字を挟んだ場合も判定し、元から `'` で始まる値は変更しません。

「保護した列」（Protected columns）は保護した列の固定識別子を列順に `;` 区切りで示します。簡易 CSV は `category`, `source`, `destination`, `details`、詳細 CSV は `time`, `action`, `relative_path`, `source`, `destination`, `decision`, `reason`, `notes`。CSV パーサで読み、挙がった列だけ先頭の `'` を1文字除くと元の値へ復元できます。空欄は保護なしです。見出しにも同じ保護を適用します。元から `'` で始まる値は変更しません。

成功・警告付き完了では出力確定を確認してください。失敗・キャンセルでは冒頭に「出力は確定していません（統合先には何も追加されていません）。」と表示し、簡易ログにコピーを列挙しません。後片付け・ロールバック失敗時はこの無追加の断定をせず、失敗と残った項目のパスを示します。警告・エラーは、できなかった処理、対象、続行または中止を記録し、システムの理由や属性名は「補足」に示します。

保存時は一時ジャーナルをストリーム変換し、全件をメモリに保持しません。次回実行と終了時に一時ログを削除します。記録失敗は統合を止めず「ログは不完全です」と理由を示します。ログは入力パスを含みます。入力・統合出力へ自動保存・同梱しません。

## 同名ファイルの採用結果

入力一覧の番号（1、2、3…）が追加順を示し、「先に追加した入力フォルダを優先」「後に追加した入力フォルダを優先」はこの順序を指します。新しい既定値は「先に追加した入力フォルダを優先」です。「統合を中止する」を含む保存済み設定は維持し、起動時に既定値を書き込みません。見出し直下には待機中・終了後は現在の設定、統合中は開始時に取得した「この実行のルール」を表示します。統合中に現在の設定が開始時のルールと異なる場合だけ「変更したルールは次回の統合から適用します」を表示し、終了時に消します。「同名ファイルの採用結果」と保存ログには実際に使用したルールを残します。

作業ログ内の独立区画「同名ファイルの採用結果」（英語: `Conflicting File Decisions`）は詳細ログオフでも表示します。内容が異なり判断した相対パスを数え、同一内容だけの省略は含めません。出力表記の相対パス、最終採用元、採用判断で不採用となった入力元、適用ルールを表示します。同一内容で省略した入力元は不採用元に含めず、時系列ログの省略記録で確認できます。画面は最大1,000件で「ほか N 件（保存ログに全件）」を表示し、件数と保存ログは全件を対象にします。未実行時と実行中は未確定の注記を表示しません。成功時は「採用結果は確定した出力に反映されています。」、失敗・キャンセル時は「出力は確定していません。以下は採用判断です。」を表示します。走査途中の失敗では「走査未完了のため、判断済み分のみ表示しています」と示します。

詳細の「フォルダ作成（一時フォルダ）」「コピー（一時フォルダ）」は構築中の処理で、確定済みの出力ではありません。「内容が同じため省略」は重複の省略です。採用判断では判定に採用元・不採用元を明示し、理由にはルール名を重ねず1文で示します。最終採用の判定には最終採用元・不採用元、補足には走査の完了状態と出力への反映状態を記録します。変更日時の比較では入力元と日時の対応を理由に含めます。
